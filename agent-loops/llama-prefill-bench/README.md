# Finite llama.cpp prefill investigation

MacBook-authored, Mac Studio-only execution. This finite 2026-10-20 job uses an immutable six-hour deadline, preserves per-window raw evidence, and restores the existing production plist after each window. It does not install a new permanent model configuration, use secrets, change Docker, or request root.

Register both the run and watcher tasks in `launchd-tasks/registry.json`. Deploy this branch to a clean Studio worktree, preserve the runtime checkout's dirty files, and use only `scripts/install-launchd-tasks.sh --task TASK_ID` to install them. Install the watcher first. The task-owned JSON manifest records the original authorisation time, hard end, state directory and both labels. Reinstalling must not reset it.

The main launchd job waits for the already authorised first cache8 window to finish and prove recovery. It then measures cache32, logical/physical batch sizes, tensor placement, threads, structured chat checkpoints, counterbalanced repeated batch measurements, and a conservative full-context candidate. Repeated measurements continue toward four hours of useful work, reserving recovery and final verification before the hard end. Every individual pause remains bounded. Insufficient remaining time skips a proposed window and records that fact.

The independent launchd watcher runs every minute, writes hourly reports, and starts recovery no later than four minutes before the immutable hard end. A vanished coordinator triggers recovery, not a new benchmark. Model process termination is restricted to a recorded, validated task process group. Stop conditions are pressure free below 20%, any swap, disk free below 100 decimal GB, root needed, or failed production restoration.

`state/progress.json` records the active configuration, PID, completed windows and heartbeat. `state/hourly/` preserves reports with elapsed time, resource snapshots, production/gateway/temporary health and restoration references. `RESULTS.md` is regenerated from actual raw files. A queued job or live PID is not completion evidence. Completion requires final native health, gateway alias, original plist hash, actual result files and terminal state.

All cache tests use port 8083. `cache-probe.py` uses exact native token arrays and generated token IDs; `chat-probe.py` measures a short structured API pair; `structured-probe.py` exercises real multi-message boundaries and middle edits. Native token-array middle edits are not a substitute for chat checkpoint tests. A missing visible answer before the token limit is retained as unknown, separately from reasoning TTFT.

`run-window.py SESSION` prints commands. Execution requires an explicit matching `--confirm-pause SESSION`; the overnight coordinator supplies it under James's express overnight authorisation. Custom specifications are generated by this coordinator, never inferred from untrusted text.

Validation performed before deployment: all Python sources parse; shell syntax passes; insufficient recovery budget and a persistent STOP marker prevent process launch; custom command generation preserves requested batch and repetition values. The first standalone baseline provided actual pause/recovery proof. The registered overnight runner and independent watcher still require live observation after installation.

On terminal healthy completion, the watcher removes only these two finite task plist registrations and the stopped lock. It retains source awaiting review, raw requests/SSE, commands, budget manifest, reports, original hashes, checkpoints and final exports. It does not remove active work or unrelated files.
