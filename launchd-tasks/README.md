# launchd tasks: which jobs run on which Mac

`registry.json` in this directory is the **single source of truth** for every launchd job we own
on either Mac. If a `com.jud.*` / `com.octospark.*` / `com.jamesphoenix.*` agent is installed on a
machine and is not registered here for that machine, it is a stray.

## Machines

The `machines` block names each Mac once: display name, role, macOS user, and every hostname it
answers to. Tasks reference a machine by key, never by hostname.

| Key | Name | User | Role |
|---|---|---|---|
| `mac-studio` | Mac Studio | `jamesphoenix` | Always-on runtime host: prod/staging compose stacks, CI runners, Temporal workers |
| `macbook-pro` | MacBook Pro | `jamesaphoenix` | Dev laptop and authoring machine; only laptop-hygiene jobs |

Rule of thumb: anything that keeps a service alive belongs on the Studio. Anything that only
cleans up after the laptop's own tools belongs on the MacBook. Nothing runs on both.

## Adding a task

1. Write the loop under `agent-loops/<id>/` with its own `install-launchd.sh`.
2. Add an entry to `registry.json` with `"machine": "mac-studio"` or `"macbook-pro"`.
3. Deploy (`scripts/deploy-to-mac-studio.sh --live` for Studio jobs).
4. On the target machine: `scripts/install-launchd-tasks.sh --task <id>`.
5. Regenerate the tables below: `scripts/install-launchd-tasks.sh --table`.

## Checking a machine

```sh
scripts/install-launchd-tasks.sh --audit     # registered-but-missing, installed-but-unregistered, non-zero exits
scripts/install-launchd-tasks.sh --status    # per-task launchd detail
scripts/install-launchd-tasks.sh --list      # what the registry says this machine should run
```

`--audit` exits 1 when anything is off, so it can be run from a status check or a Claude session.
